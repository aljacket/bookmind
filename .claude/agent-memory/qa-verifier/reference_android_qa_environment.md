Setup that worked on 2026-10-08 (card #50, Capacitor 8.5.3 / API 36):

-   **Worktree**: the PR branch is usually checked out in the engineer's worktree (`.claude/worktrees/agent-*`), so `git worktree add` the branch fails → use `git worktree add --detach ../bookmind-qa-<n> origin/<branch>`. A fresh worktree has no `android/local.properties`: export `ANDROID_HOME=$HOME/Library/Android/sdk` for gradle (don't write files in the repo). `origin/main` can be ahead of local `main`: diff against `origin/main`.
-   **JDK**: Capacitor 7/8 Gradle needs JDK 21 → `JAVA_HOME=$HOME/.sdkman/candidates/java/21.0.12-tem`, prepend `$JAVA_HOME/bin` to PATH. Capacitor 6 builds with `17.0.9-tem`. Android Studio JBR is JDK 25: do not use. No `timeout`/`gtimeout` on the Mac: use `run_in_background`.
-   **Host has 8 GB RAM**: with Chrome + Claude open, swap is nearly full. Leftover Gradle daemons make the emulator hang (QEMU "hanging thread", crash 139, "System UI isn't responding", black app window). Run `./gradlew --stop` (and kill old JDK 17 daemons) **before** booting an emulator; boot with `-no-snapshot`; if System UI ANR shows, tap Wait, give it ~45 s, then force-stop/relaunch the app.
-   **Build**: `npm run build && npx cap sync android && (cd android && ./gradlew :app:assembleDebug --console=plain)`. Never `cap sync` without `android`. aapt2: `~/Library/Android/sdk/build-tools/35.0.0/aapt2 dump badging <apk> | grep -i sdkversion`.
-   **AVDs**: Pixel_9_API_36 (1080x2424 @420, DPR 2.625, status bar 142 px portrait / 137 landscape, gesture nav 63 px), Pixel_Tablet_API_36 (natural landscape 2560x1600, DPR 2, status bar 48 px), Pixel_9_API_35. One emulator at a time. Poll `adb shell getprop sys.boot_completed`. Both API 36 AVDs ship WebView 133 (<140) → `--safe-area-inset-*` = 0; the ≥140 path can only be simulated.
-   **Rotation**: `settings put system accelerometer_rotation 0` + `user_rotation 1|0`; the setting can revert after an app restart, re-check `dumpsys window displays | grep cur=`. Restore `accelerometer_rotation 1` at the end.
-   **Drive the WebView**: `adb forward tcp:9333 localabstract:webview_devtools_remote_$(adb shell pidof com.bookmind.app)`; Node CDP script with `Runtime.evaluate`. `/json` lists two "page" targets: pick the one whose description has `"attached":true`. Wait ~14 s after launch before touching `#app` (cold WebView is slow). Keyboard state: `dumpsys input_method | grep mInputShown`. Programmatic `focus()` does NOT open the soft keyboard: tap with `adb shell input tap` (device px = CSS px × DPR + status bar). `input keyevent 4` closes the IME, `66` = Enter (submits the chat).
-   **Fake user (no credentials)**: `document.querySelector('#app').__vue_app__.config.globalProperties` → `$pinia._s.get('auth').setUser({uid,displayName,email})` then `$router.push('/preferences')`. Production builds do not expose `__vueParentComponent`: drive the UI (set textarea value + `input` event + click Send) instead of touching component state.
-   **Backend**: the clarify/recommendations endpoints need real Firebase tokens. Simplest: mock. On the device, CDP `Fetch.enable` on `*localhost:8000*` + `Fetch.fulfillRequest` (answer OPTIONS with CORS headers, switch ok/fail through a mode file to get the error state). In the browser, a tiny Node `http` server on 127.0.0.1:8000 with CORS.
-   **Browser baseline**: `npx vite preview --port 4173` (PR) / 4174 (main, separate detached worktree). chrome-devtools MCP: `emulate` reloads the page (the fake user is lost, redo setup); `take_screenshot filePath` refuses the scratchpad (take it inline); screenshots after switching mobile emulation can render garbled. Best tool for size matrices: **same-origin iframes** of the given width x height in one `evaluate_script` (each has its own viewport, so `dvh` is correct): set the user in `iframe.contentDocument`, run the flow, measure, remove. Run the identical script on main and PR. Lighthouse MCP has no performance category → `performance_start_trace` with 4x CPU + Slow 4G.
-   **"Reachable" check**: for each control, `scrollIntoView({block:'nearest'})` then compare with the card rect (clipped?) and `visualViewport` (reachable?). Confirm on the device with a real `adb shell input swipe` in the side gutter outside the card (the chat log captures swipes inside the card). Remember to `scrollTo(0,0)` after measuring. A full verification round (build + phone + tablet + web matrix) takes ~25 min.
-   **Upgrade test**: install main's APK, seed IndexedDB `BookMindDB`/`readingList`, then `adb install -r` the PR APK; origin stays `https://localhost`.
